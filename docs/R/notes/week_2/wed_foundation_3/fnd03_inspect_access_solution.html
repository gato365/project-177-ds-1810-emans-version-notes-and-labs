0 · Today’s job 2 min

You get handed a dataset. Before any analysis, you must answer three questions: What is this? How big is it? What’s inside? Today is those three questions, as functions — and then, once you know what’s inside, how to reach in and take a piece.

3 · How big is data? 10 min

LM9 — storage units (4 min). Data size is measured in bytes: byte → KB (thousand) → MB (million) → GB (billion) → TB (trillion). Rough anchors: this class’s survey ≈ a few KB · a semester of sensor logs ≈ MBs · a music library ≈ GBs · a national census extract ≈ TBs.

# LM9: how big are OUR objects?
object.size(airquality)
5632 bytes
object.size(iris)
7256 bytes
object.size(mtcars)
7208 bytes

Q5. Order the three from smallest to largest: airquality (≈ 5.6 KB) < mtcars (≈ 7.2 KB) < iris (≈ 7.8 KB)

Why it matters: R holds data in memory. A 2 GB file on a 8 GB laptop imports; a 200 GB file does not — you’d need different tools. File size is the first thing to check before importing, which is exactly where next week begins.

Q6. Your laptop has 8 GB of memory. Roughly how many copies of a 500 MB dataset could fit at once (ignore overhead)? About 16 — 8 GB ≈ 8,000 MB, and 8,000 / 500 = 16.

TipQ5 & Q6 answers
  • Q5 actually run it: airquality ≈ 5.6 KB, mtcars ≈ 7.2 KB, iris ≈ 7.8 KB → airquality < mtcars < iris
    • mtcars is small in rows but its row names cost bytes — a fun 20-second aside if asked; otherwise just confirm the order
  • Q6 about 16 copies — 8 GB ≈ 8,000 MB; 8,000 / 500 = 16
    • honest version: overhead means fewer in practice
    • the point is order-of-magnitude reasoning, which is sub-outcome 1.12’s whole job

5 · Exit question 8 min

You’re handed mysterydata, a data frame you’ve never seen. Write the three lines you’d run FIRST, in order, and say what each tells you. Then write ONE more line that pulls out a single column named score as a vector.

# your three inspection lines:
glimpse(mysterydata)      # structure: rows, columns, names, types
summary(mysterydata)      # ranges + WHERE the NAs are
head(mysterydata)         # what the values actually look like

# your one access line:
mysterydata$score         # one column, as a vector

Your explanation: glimpse() first tells me the shape (rows, columns), the names, and the type of every column. summary() then gives the range of each numeric column and, crucially, where the NAs are. head() shows what the values actually look like so I can sanity-check the types. Then mysterydata$score pulls the one column out as a vector (so would mysterydata[["score"]]; mysterydata["score"] would still be a data frame).

TipModel answer 
glimpse(mysterydata)      # structure: rows, columns, names, types
summary(mysterydata)      # ranges + WHERE the NAs are
head(mysterydata)         # what the values actually look like

mysterydata$score         # one column, as a vector
  • Passes: any three of {glimpse/str, summary, head/tail, dim/nrow+ncol, names} with correct one-line justifications
  • The access line must be $score or [["score"]] (a vector) — ["score"] is a data frame: half credit with the explanation
  • The habit being graded: inspect before you compute — the E stage’s second half, forever
