1 · Data types 28 min

1.1 · The types, defined first (before any code) 5 min

Every single value in R has a type. Here are the ones you’ll live with, each with a Cal Poly example:

Type What it is Example value
numeric (double) a number that can have decimals 4.75 — a latte at Julian’s
integer a whole number (written with an L) 38L — people in the Rec Center at 7 am
character text, in quotes "Scout Coffee"
logical TRUE or FALSE TRUE — the drink is iced
factor text from a fixed menu of allowed values "morning" from {morning, afternoon, evening}
Date / date-time a calendar date; a date and clock time 2026-09-22 / 2026-09-22 07:00:00
NA a missing value — a hole, not a type of its own the headcount nobody recorded
ImportantTeaching note — definitions before class()
  • Read the table row by row before anyone runs code. The order today is: define the type → then discover it with class()
  • Ask: “If I write a latte price, which row?” (numeric) “The name of the shop?” (character) “Whether it’s iced?” (logical)
  • NA gets one sentence: it’s a placeholder for “nobody knows,” and it can sit inside any type

1.3 · Three families: quantitative, categorical, other 6 min

R’s types sort into three families you’ll use to pick plots and summaries all term:

Family Question it answers R types Cal Poly examples
Quantitative how much? how many? — you can average it numeric, integer latte price (4.75), Rec Center headcount (38), miles from campus (2.3)
Categorical which kind? which group? — you count it character, factor, logical coffee shop ("Julian's", "Starbucks", "Scout"), time slot ("morning"), iced (TRUE)
Other (time/date) when? — ordered, but not a plain number Date, date-time the day you bought the latte, the clock time you swiped into the Rec

Q2. Which family: (a) the number of people in the Rec Center at 5 pm · (b) the shop that made your latte · (c) the date of the game vs. UCSB · (d) whether you bought a latte today (yes/no)?

Your answer: (a) quantitative · (b) categorical · (c) other — a date · (d) categorical — a logical is a two-level category.

TipQ2 answer + why the families matter
  • Q2 (a) quantitative (b) categorical (c) other / date (d) categorical — logical is a yes/no category
  • Why bother: quantitative → histograms and means; categorical → bar charts and counts; dates → line plots over time. Week 3’s plots pick themselves once you name the family
  • Trap to name now: a number can be categorical. Your student ID is digits, but averaging student IDs is nonsense

A small distinction — “string” vs “character”. Other languages call text a string. R calls the type character, and one piece of text ("Scout Coffee") is a string — a character value of length one. So "latte" is a string, its class is character, and c("latte", "mocha") is a character vector of two strings. You’ll hear both words; they are not in conflict.

1.4 · Factors vs characters — why it matters 6 min

LM4 — the same text, two types (4 min). Rec Center headcounts come with a time slot. As character, the slots are just words; as a factor, they come with a fixed menu of allowed values (levels) in an order you choose:

# LM4: character vs factor
slot_chr <- c("evening", "morning", "afternoon", "morning", "evening", "evening")
slot_fct <- factor(slot_chr, levels = c("morning", "afternoon", "evening"))

class(slot_chr)
[1] "character"
class(slot_fct)
[1] "factor"
levels(slot_fct)
[1] "morning"   "afternoon" "evening"  
table(slot_chr)   # alphabetical — afternoon first
slot_chr
afternoon   evening   morning 
        1         3         2 
table(slot_fct)   # the order YOU chose — morning first
slot_fct
  morning afternoon   evening 
        2         1         3

👀 Variables check. slot_chr and slot_fct are both listed — same six values, but Variables describes one as character and one as factor with 3 levels. That description IS the type.

Q3. How many levels does slot_fct have, and what order did we give them? Why would that order matter on a bar chart?

Your answer: 3 levels — morning, afternoon, evening. A bar chart follows the levels, so the factor plots the day in time order; the character version plots alphabetically (afternoon, evening, morning), which reads as nonsense.

TipQ3 answer — the two reasons factors exist
  • Q3 3 levels, in the order morning → afternoon → evening
  • Reason 1 — order. Characters sort alphabetically; factors sort by your levels. Every plot and table of a categorical variable inherits that order
  • Reason 2 — a fixed menu. A factor knows "night" is not allowed (it becomes NA); a character column will happily accept "Morning", "morning ", and "AM" as three different groups. Factors are how you catch typos in categories
  • Rule of thumb to leave them with: character = free text (names, comments); factor = a category with a known set of values
  • The menu metaphor pays rent in week 6 when forcats arrives

Q5. c(4.75, "five", 5.95) has class character. In one phrase, why?

Your answer: A vector holds one type, so R coerces everything to text.

TipQ5 answer — coercion
  • Q5 character

  • This is coercion, arriving by accident rather than lecture — say the word once
  • They meet it again when a price column imports as <chr> because one row says “free”

LM9 — tribble: a tibble typed row by row, with a factor inside (3 min). Rec Center headcounts, three slots. Note the slot column is made a factor with the order we want:

# LM9: Rec Center headcounts — a tribble, then a factor column
rec <- tribble(
  ~slot,       ~hour, ~people,
  "morning",     7,     38,
  "afternoon",  13,    112,
  "evening",    18,    164
)
rec$slot <- factor(rec$slot, levels = c("morning", "afternoon", "evening"))
rec
NoteLM9 — read the type tags
  • slot prints as <fct>, hour and people as <dbl> — categorical, quantitative, quantitative. The tibble is telling you the families
  • rec$slot <- factor(...) is the first time they change a column’s type — one sentence: “we told R this text is a category with an order”

2b · When things break 6 min

Today’s errors are type and structure errors. Same rule as last week: read the message slowly, name the family, then fix it.

YT5 (6 min). Each chunk below has ONE bug. Read the error (or the silent wrong answer!), fix it in place, and write the error family in the comment.

# YT5a — error family: ____
price <- c(4.75, "5.45", 5.95)
mean(price)
# YT5a — error family: coercion — one quoted number turned the whole vector to character; mean() warns and returns NA
price <- c(4.75, 5.45, 5.95)
mean(price)
[1] 5.383333
# YT5b — error family: ____
tibble(shop = c("Julian's", "Starbucks", "Scout Coffee"), price = c(4.75, 5.45))
# YT5b — error family: column lengths don't match (size 3 vs size 2) — every column must be the same length
tibble(shop = c("Julian's", "Starbucks", "Scout Coffee"), price = c(4.75, 5.45, 5.95))
# YT5c — error family: ____
factor(c("morning", "Morning", "evening"), levels = c("morning", "afternoon", "evening"))
# YT5c — error family: a value not on the factor's menu becomes NA (no error!) — "Morning" ≠ "morning"
factor(c("morning", "morning", "evening"), levels = c("morning", "afternoon", "evening"))
[1] morning morning evening
Levels: morning afternoon evening
CautionYT5 answers — three error families for types & structures
  • YT5a c(4.75, "5.45", 5.95) → the vector is character; mean() warns “argument is not numeric or logical: returning NA”
    • family: coercion — one text value drags the whole vector to text. The tell is the quotes in the printout
    • fix: remove the quotes (later: as.numeric())
  • YT5b Tibble columns must have compatible sizes — size 3 vs size 2
    • family: mismatched column lengths — the error names the sizes and the column
    • fix: give every column the same number of values
  • YT5c no error at all — "Morning" prints as <NA>
    • family: value not in the factor’s levels → silently becomes NA (the sneakiest of the three; the menu metaphor from §1.4 explains it)
    • fix: match the level exactly ("morning") — R is case-sensitive
  • Two of the three are silent: no red text. Say it: the absence of an error is not the presence of a right answer — print your objects
