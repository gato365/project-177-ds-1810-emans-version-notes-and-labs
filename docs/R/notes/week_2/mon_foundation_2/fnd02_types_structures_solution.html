library(tidyverse)

0 · The one distinction, and your own chunks (8 min)

Write the sentence on the board and leave it there all class: type = one value’s nature; structure = the container.

Teaching note — inserting chunks. Demonstrate the shortcut (Cmd/Ctrl + Shift + I) once, slowly, on the projector: cursor on a blank line, press it, the fence appears, type 1 + 1, run. Then YT0 — walk the room for 2 minutes and make sure every screen shows output under a student-made chunk before moving on. This is the one thing today that can’t be caught up on later; every later YT depends on it. Students who type the fence by hand are fine — the skill is “I can make a chunk,” not the shortcut.

# YT0
1 + 1
[1] 2

1 · Data types (22 min)

# LM1 — expected: "numeric", "integer", "character", "logical"
class(4.75)
[1] "numeric"
class(4L)
[1] "integer"
class("latte")
[1] "character"
class(TRUE)
[1] "logical"

Q1 note: most students predict "numeric" for 4L — good; the surprise is the point. The L suffix is worth 30 seconds, no more.

# LM2 — "double" vs "integer"
typeof(4.75)
[1] "double"
typeof(4L)
[1] "integer"
# LM3 — factor with 3 levels
class(iris$Species)
[1] "factor"
levels(iris$Species)
[1] "setosa"     "versicolor" "virginica"

Q2: 3 levels — setosa, versicolor, virginica. Teaching note: the menu metaphor (“a factor is text with a fixed menu”) pays rent in week 6 when forcats arrives.

# LM4
today <- Sys.Date()
class(today)
[1] "Date"
right_now <- Sys.time()
class(right_now)
[1] "POSIXct" "POSIXt"

Expected classes: "Date" and "POSIXct" "POSIXt" — say “date-time” and move on; lubridate handles the ugliness in week 4.

# LM5
sum(is.na(airquality$Ozone))
[1] 37

Q3: 37 missing. Real 1973 NYC air data — the missing values are genuinely missing, not planted. First appearance of the is.na() + sum() idiom; students will use it in every cycle.

# LM6 — any correct fills, e.g.
is.numeric(4.75)
[1] TRUE
is.character("latte")
[1] TRUE
is.logical(TRUE)
[1] TRUE
is.factor(iris$Species)
[1] TRUE
# YT1 — expected: "character", "logical", "numeric", "Date"
class("TRUE")
[1] "character"
class(3 > 2)
[1] "logical"
class(mtcars$cyl)
[1] "numeric"
class(Sys.Date() + 7)
[1] "Date"

YT1 teaching note: the surprise is almost always "TRUE" — quotes make it text. Second surprise: 3 > 2 produces a logical; comparisons are how logicals get made in practice (filter() in two weeks). mtcars$cyl being numeric though it only takes 4/6/8 is a preview of activity item E.

2 · Data structures (30 min)

# LM7
drinks <- c("latte", "drip", "mocha")
drinks
[1] "latte" "drip"  "mocha"
length(drinks)
[1] 3
class(drinks)
[1] "character"
# YT2
prices <- c(4.75, 2.75, 5.25)
sizes  <- c("small", "medium", "large")
iced   <- c(TRUE, FALSE, TRUE)
prices; sizes; iced
[1] 4.75 2.75 5.25
[1] "small"  "medium" "large" 
[1]  TRUE FALSE  TRUE
class(prices); class(sizes); class(iced)
[1] "numeric"
[1] "character"
[1] "logical"
c(1, "two", 3)
[1] "1"   "two" "3"  
class(c(1, "two", 3))
[1] "character"

Q4: character. A vector holds one type, so R converts everything to the type that can hold all of it — text. This is coercion, arriving by accident rather than lecture. Say the word once; students meet it again when a numeric column imports as <chr> because of one stray “N/A”.

# LM8
menu_df  <- data.frame(drink = drinks, price = c(4.75, 2.75, 5.25))
menu_tbl <- tibble(drink = drinks, price = c(4.75, 2.75, 5.25))
menu_df
menu_tbl

Q5 model answers (any one): the tibble announces its dimensions (# A tibble: 3 × 2); the tibble shows column types (<chr>, <dbl>); the data frame shows row numbers without types. Framing: a tibble IS a data frame with better manners — we’ll say “data frame” for both.

# YT3
menu <- tibble(drink = drinks, price = prices, size = sizes, iced = iced)
menu
nrow(menu); ncol(menu); class(menu)
[1] 3
[1] 4
[1] "tbl_df"     "tbl"        "data.frame"
# YT3 — the deliberate break
tibble(drink = drinks, price = c(4.75, 2.75))
#> Error: Tibble columns must have compatible sizes.
#> • Size 3: Existing data.
#> • Size 2: Column `price`.

YT3 teaching note: the error is a good error — it names the sizes and the column. Have someone read it aloud. “Every column the same length” is now something they’ve felt, not heard. (class(menu) returns three things — tbl_df, tbl, data.frame — say “it’s a data frame, with extra labels” and move on.)

# LM9 — tribble, briefly
tribble(
  ~drink,  ~price,
  "chai",   4.50,
  "espresso", 3.00
)
# LM10 — list
my_list <- list(name = "week 2", nums = c(1, 2, 3), data = menu_tbl)
my_list
$name
[1] "week 2"

$nums
[1] 1 2 3

$data
# A tibble: 3 × 2
  drink price
  <chr> <dbl>
1 latte  4.75
2 drip   2.75
3 mocha  5.25
length(my_list)
[1] 3

Junk-drawer framing: a list holds anything, including a whole tibble. length() is 3 — three drawers, whatever’s inside them. Plant the flag: “when we pull data from an API in week 8, it arrives as a list.”

# YT4 — e.g.
me <- list(first = "Eman", n_classes = 4, menu = menu)
me
$first
[1] "Eman"

$n_classes
[1] 4

$menu
# A tibble: 3 × 4
  drink price size   iced 
  <chr> <dbl> <chr>  <lgl>
1 latte  4.75 small  TRUE 
2 drip   2.75 medium FALSE
3 mocha  5.25 large  TRUE 
# LM11 — matrix, briefly
matrix(1:6, nrow = 2)
     [,1] [,2] [,3]
[1,]    1    3    5
[2,]    2    4    6

Q6: a data frame — a matrix forces every cell to one type, so names + numbers would coerce the numbers to text (same coercion as Q4, now at the structure level).

3 · In-class activity (15 min)

One chunk per item — check that students actually made six chunks; the habit of “one idea, one chunk” is what makes ETV documents readable.

# A — Structure
class(iris)          # "data.frame"
[1] "data.frame"
# B — Type
class(iris$Sepal.Length)   # "numeric"
[1] "numeric"
# C — Type question (is.na tests values)
sum(is.na(airquality$Solar.R))   # 7
[1] 7
# D — Structure built by the student, e.g.
foods_tbl <- tibble(
  food   = c("tacos", "pho", "pizza"),
  rating = c(10, 9, 8)
)
foods_tbl
# E — Type; stored as integer, arguably should be a factor (or a Date)
class(airquality$Month)
[1] "integer"
# F — Structure: a list holding a tibble and a vector
food_places <- list(
  foods  = foods_tbl,
  places = c("truck on Higuera", "home", "campus")
)
food_places
$foods
# A tibble: 3 × 2
  food  rating
  <chr>  <dbl>
1 tacos     10
2 pho        9
3 pizza      8

$places
[1] "truck on Higuera" "home"             "campus"

Answers: A = S · B = T · C = T (7 missing) · D = S · E = T (“integer”; a factor would make sense since 5–9 are labels, not amounts) · F = S. E is the discussion item: the type R stores is not always the type the data means — that’s the whole reason mutate() + factor() exists.

4 · Exit question (5 min)

Model answer: “A data type is what one value is — 4.75 is numeric. A data structure is the container holding values — my menu tibble is a data frame whose iced column is logical.” Any answer pairing one correct type example with one correct structure example passes; at least one example should be from a student-built object.
