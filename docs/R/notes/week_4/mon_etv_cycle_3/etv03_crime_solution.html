ETV Cycle 03 — [Crime Data: Title TBD]

STAT/DATA 1810 · In-class activity · SOLUTION (TEMPLATE)

Author

Instructor key

0 · Context & ethics (10 min) — instructor script

Run all five beats; the two non-negotiables are Measurement (these records count reports and enforcement, not crime itself) and Consequences (a chart of this data can move policy, prices, and policing; the title must say “reported”). Model sentence for the student prompt: “Because unreported offenses never enter the data, every count is a floor, not a level — and the floor is lower in communities that distrust reporting.”

1 · The central question

[COMMITTED QUESTION — recommended shape: “How do reported [offense category] incidents vary by hour of day?” It exercises the timestamp, gives geom_point a natural x-axis, and regenerates every semester with new data.]

2 · E — Extraction (12 min)

library(tidyverse)

# LM1: load — note for students: load() puts objects INTO the environment;
# there is no assignment arrow, which is exactly why we inspect ls() next.
load("Data/[FILENAME].RData")
ls()

Expected: [OBJECT_NAME] appears. Contrast with read_csv() on the board: read functions return, load() injects. This is the whole CLO 2.7 lesson in one line.

# LM2: inspect
glimpse([OBJECT_NAME])

Expected: [rows], [date range], one row = one reported incident.

3 · T — Transformation (28 min)

# LM3: select
crime_small_df <- [OBJECT_NAME] |>
  select(offense, date_time, [neighborhood_or_beat])
# LM4: filter — committed rule: [e.g., offense %in% c(...), complete
# date_time, incidents within the chosen year]
crime_clean_df <- crime_small_df |>
  filter([RULE])

nrow(crime_small_df) - nrow(crime_clean_df)

Expected: [n removed]. Defense: [state it — and connect to underreporting: we can defend removing unusable records; we cannot recover unreported incidents, and the answer must say so].

# LM5: recode/create — recommended: hour of day
crime_clean_df <- crime_clean_df |>
  mutate(hour = lubridate::hour(date_time))

(If lubridate hasn’t formally arrived yet, this is a one-function toolbox loan — name it, use it, move on.)

# LM6: group + summarize + arrange
crime_summary_df <- crime_clean_df |>
  group_by(hour) |>
  summarize(n = n()) |>
  arrange(desc(n))

crime_summary_df

Expected: [peak hours — typically late evening for most offense mixes].

4 · V — Visualization & summary (20 min)

# LM8: the point plot
ggplot(crime_summary_df, aes(x = hour, y = n)) +
  geom_point(size = 3, color = "#12263A") +
  labs(
    x = "Hour of day",
    y = "Number of reported incidents",
    title = "Reported [offense] incidents peak in the [period]",
    subtitle = "Reports, not occurrences — see limitations"
  )

Expected pattern: [describe once committed]. The subtitle is mandatory — it is the Transparency beat (12.6) enforced in the artifact itself.

5 · Interpretation & final answer (10 min) — model answer shape

“Reported [offense] incidents are concentrated in [period], with roughly [X]× as many reports at the peak hour as at the quietest hour. This pattern describes when incidents are REPORTED, which reflects both when events occur and when people or patrols are positioned to report them — enforcement and reporting behavior are baked into every count. [One consequence sentence: what this chart should and should not be used to decide.]”

Trio check (CLO 4.5): pattern ✔ · magnitude ✔ · caveat ✔ — same rubric as Cycles 01 and 02, now carrying the heaviest ethical weight of the three.
