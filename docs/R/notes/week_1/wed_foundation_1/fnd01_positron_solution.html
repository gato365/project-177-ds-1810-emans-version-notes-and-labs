Foundations 01 — Positron and the R Environment

STAT/DATA 1810 · Week 1 Wednesday · SOLUTION

Author

Instructor key

0 · What you are looking at (12 min)

The panes (6 min)

Teaching note: have students physically point at each pane; the checklist is the activity. Positron names differ from RStudio — say Variables (not Environment) and Editor (not Source) consistently, since that is what students see on screen. Terminal/Viewer/Connections get one sentence each — resist the tour becoming the lesson.

YT1: Variables. YT2: the Editor (this .qmd).

The Session (6 min)

Teaching note — the Session tab. Point at the top-right interpreter label (R 4.x.x). Click it once so they see the menu: the running session, Restart, Shutdown, and any other interpreters. Say the three facts (memory / restartable / replaceable) and move on. The payoff comes in §4 LM11 when they restart for real. Show that Variables is empty now — that “before” picture makes the restart in §4 land.

Q1 model answer: the Console runs code once and forgets it; the Editor holds code you keep, so you can re-run everything tomorrow.

1 · Running code and code chunks (12 min)

LM1: the up-arrow trick saves students dozens of retypes this term — worth the 20 seconds.

LM2 teaching note — anatomy of a chunk. Put the cursor on the ```{r} line and name its parts out loud: fence, {r} = “this is R”, fence. Then click the play button so they see output land both under the chunk and in the Console. The sentence to leave them with: “a chunk is a saved bundle of Console lines.” Students create their own chunks starting Monday (Foundations 02) — today they only run and edit ours.

# LM2
2 + 2
[1] 4
3 * 7
[1] 21
10 / 4
[1] 2.5

LM3: one sentence on #| options is enough. They’ll write #| label: and #| eval: false themselves in ETV cycles.

# YT3
5 - 4
[1] 1
100 / 8
[1] 12.5
2^10
[1] 1024

Expected: 1 · 12.5 · 1024. Q2: both.

2 · Objects and assignment (16 min)

# LM4
cups <- 3
cups
[1] 3
# LM5 — prediction: 13.5
price <- 4.50
total <- cups * price
total
[1] 13.5
# LM6
cups <- 10
total
[1] 13.5

Q4 model answer: total was computed at the moment the <- line ran, using cups = 3. Changing cups later doesn’t re-run old lines — R objects store values, not formulas. This is the single most important idea of the day; spend the full minutes here. (Spreadsheet contrast lands well: Excel cells recompute; R objects don’t.)

# YT4 — any sleep value; e.g.
hours   <- 7
minutes <- hours * 60
minutes
[1] 420
hours   <- 8
minutes            # still 420 — same lesson as Q4, now self-discovered
[1] 420

YT4 (d): minutes does not change. This is Q4 again, but the student built it, so it sticks. Have two students say their prediction and result aloud. Then point at Variables: cups, price, total, hours, minutes — five objects, all session memory.

3 · Functions, packages, help (20 min)

# LM7
mean(mtcars$mpg)
[1] 20.09062
nrow(mtcars)
[1] 32

Expected: 20.09062 · 32.

# YT5
max(mtcars$hp)
[1] 335
min(mtcars$mpg)
[1] 10.4
ncol(mtcars)
[1] 11
round(mean(mtcars$mpg), 1)
[1] 20.1

Expected: 335 (the Maserati Bora) · 10.4 · 11 · 20.1. Part (d) is the first nested call — say “inside out” once; don’t dwell.

Q5 model answer: na.rm = TRUE tells mean() to remove NA values before computing; the default FALSE returns NA if any value is missing. (Plant the flag: this argument returns in Foundations 03 and every ETV cycle.)

YT6: digits, default 0. The purpose is reading a Usage line, not the fact itself.

library(tidyverse)

Q6: install runs once per computer; library runs once every session. Analogy that sticks: install = buying the drill; library = taking it out of the garage.

4 · When things break (12 min)

meen(mtcars$mpg)
#> Error in meen(mtcars$mpg) : could not find function "meen"
# LM10 fixed
mean(mtcars$mpg)
[1] 20.09062

Q7 model answer: “could not find function” means the name doesn’t exist — a typo, or a package not loaded. Teaching note: name the two most common error families now: could not find function (typo/library) and object not found (name typo / never created). Students who can classify an error stop fearing errors.

YT7 answers:

  • 7a mtcars$mgp → returns NULL, and mean warns “argument is not numeric or logical: returning NA”. Family: column-name typo ($ on a missing column gives NULL, not an error — worth saying, since it’s the sneakiest of the three). Fix: mpg.
  • 7b Mtcars → Error: object 'Mtcars' not found. Family: object not found (R is case-sensitive). Fix: mtcars.
  • 7c missing ) → the Console shows a + prompt waiting for more; in a chunk, “unexpected end of input”. Family: unbalanced parentheses. Fix: add ). Show them Escape in the Console to get out of a + prompt.
mean(mtcars$mpg)
[1] 20.09062
mean(mtcars$mpg)
[1] 20.09062
mean(mtcars$mpg)
[1] 20.09062

LM11 — restart for real. Everyone restarts. Variables empties. Then Q8: cups gone · code still here · re-running §2 takes ~10 seconds. That 10-second recovery is the argument for putting code in the file.

5 · Save & render (8 min)

Exit model answer: cups lives in Variables (gone after restart); this .qmd lives in the Editor (survives). The code that recreates cups survives — which is the entire argument for reproducible documents, made on day one without ever saying “CLO 9.”
